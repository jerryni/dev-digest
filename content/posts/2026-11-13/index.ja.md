# 11月13日 · 今日のテック厳選10本

## 本日のサマリー

今日は、言語の節目よりも運用の基本が目立ちます。古い脆弱性の扱い、SaaS 障害への備え、AI コーディング支援のコンテキスト管理は、いずれも境界を明文化して検証する仕事です。

## Picks

### 1. [Rust 1.100](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/)
`Hacker News · プログラミング言語`

Rust 1.100 は大きな節目ですが、導入判断ではプロジェクト内で何が簡単になるかを見るべきです。MSRV、依存関係、CI の組み合わせを同時に見直すと、アップデートの効果が実装に届きます。丸いバージョン番号そのものは移行計画ではありません。

### 2. [22年前の PostgreSQL バグが RCE に至るまで](https://mehmetince.net/part-3-6-how-i-ended-up-turning-a-22-year-old-postgresql-type-confusion-primitive-into-rce-cve-2026-6460/)
`Hacker News · セキュリティ`

この解析は PostgreSQL の型混同プリミティブがリモートコード実行へつながる道筋を追います。成熟したミドルウェアでも、古い前提が新しい接続方法や権限設計と組み合わさると危険になります。DB のパッチはバージョン更新だけで終わらせず、資産棚卸しと復旧手順の確認まで含めたいところです。

### 3. [Foundation Models framework](https://developer.apple.com/foundation-models-framework/)
`Hacker News · プラットフォーム API`

Apple がオンデバイスモデルへのアクセスを公式フレームワークとして提供します。プライバシーと応答速度に利点がありますが、OS バージョンや利用可能な機能の差は製品側で吸収する必要があります。モデルが使えない時でも成立する体験を先に設計するのが堅実です。

### 4. [modern-web-guidance-src](https://github.com/GoogleChrome/modern-web-guidance-src)
`GitHub Trending · Web 開発`

Google Chrome の、コーディングエージェント向け Web ベストプラクティス集です。レビュー観点やチーム規約の材料としては有用ですが、プロンプトへ一括貼り付けして終わりにはできません。採用したルールをバージョン管理し、推奨の変化が自分たちの設計をどう変えたか追えるようにしましょう。

### 5. [Codex Security CLI と TypeScript SDK](https://github.com/openai/codex-security)
`GitHub Trending · アプリケーションセキュリティ`

脆弱性の検出、検証、修正を支援する Codex Security が Trending に入っています。自動検出は一次調査を速くしますが、検証なしではアラートの山を増やすだけになりがちです。まず対象リポジトリを限定し、採用・修正・誤検知の判断者を明確にすると運用しやすくなります。

### 6. [Microsoft 365 のサービス劣化を追うスレッド](https://www.v2ex.com/t/1256329)
`V2EX · 開発者コミュニティ`

Microsoft サービスの広い障害を、利用者側から追った話題です。ステータスページは提供元の状況を示しますが、自社の認証、連絡、顧客対応のどこが止まるかまでは示してくれません。重要な SaaS については、利用できない一日を前提にした手順を一度試しておく価値があります。

### 7. [スマホで完全な購読 URL をコピーすると漏えいしうる](https://www.v2ex.com/t/1256332)
`V2EX · セキュリティ衛生`

完全な購読 URL にはトークンが含まれることがあり、モバイルのクリップボード、チャット、スクリーンショット経由で漏えいします。URL をただの文字列として扱わないことが第一歩です。露出が疑われたら投稿を消すだけでなく、トークンをローテーションしてください。

### 8. [Node.js 22、24、26 の脆弱性が自分のアプリに影響するか確認する方法](https://zenn.dev/)
`Zenn · JavaScript セキュリティ`

Zenn のトレンド記事は、Node.js の脆弱性対応を影響調査として整理しています。実際にデプロイされているランタイム、該当機能、ベースイメージを確認してから更新計画を立てるのが順番です。緊急アップデートほど、小さくても互換性テストを省かない方が結果的に速くなります。

### 9. [Claude Code に忘れさせてトークン使用量を減らす](https://zenn.dev/)
`Zenn · AI 支援開発`

この実践例の要点は、エージェントのコンテキストを予算のある依存関係として扱うことです。永続的なプロジェクト規則は残し、古くなった実行ログは捨て、必要な事実は検索で取り直します。コンテキストを軽くするとコストだけでなく、重要な制約が埋もれにくくなります。

### 10. [Playwright が Bun を正式サポート](https://www.publickey1.jp/blog/26/playwrightbun.html)
`Publickey · テスト`

Publickey によると、Playwright 1.65.0 は Bun 上でのテストランナー実行を正式にサポートしました。Bun を標準化しているチームには自然な選択肢ですが、E2E テストの安定性はブラウザの固定、CI イメージ、フィクスチャの再現性で決まります。共有パイプラインを変える前に、全スイートで比較しましょう。
