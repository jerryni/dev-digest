# 10月25日 · 今日のテック厳選8本

## 本日のサマリー

本日は、速さの主張よりも運用上の境界をどう明確にするかがテーマです。依存ライブラリ、AI エージェント、言語ランタイムのどれでも、観測・権限・復旧の設計が成果を左右します。

## Picks

### 1. Goose Programming Language のスタック中心設計 [HN]

[プロジェクトを読む](https://aardappel.github.io/goose/)

Goose はヒープ、GC、ライフタイム注釈なしでメモリ安全を目指すシステム言語です。データをインラインに置く設計は魅力的ですが、ランダムアクセスや動的ディスパッチを制限するという明確な交換条件があります。ベンチマークの数値だけでなく、その制約が自分のワークロードに合うかを見るべきでしょう。

### 2. HTTP2Shell はまず資産棚卸しから [HN]

[脆弱性レポートを読む](https://www.aikido.dev/blog/python-packages-vulnerable-node2shell-brotli-cve-2026-111497)

Node2Shell から派生した HTTP2Shell の話題は、HTTP スタックがアプリの深い依存関係に入り込みやすいことを示します。パッケージを更新する前に、公開中のエンドポイント、実行時のライブラリ、コンテナイメージを対応付けることが重要です。更新後の監視とロールバックまで含めて初めて、修正は運用可能になります。

### 3. 分散 SQLite を12年運用して見えたこと [HN]

[記事を読む](https://philipotoole.com/twelve-years-of-distributed-sqlite/)

分散 SQLite の12年を振り返る記事は、小さなデータベースにも複製と障害対応の現実があることを丁寧に伝えます。複雑さを消すのではなく、理解できる場所へ移せているかが設計の評価軸になります。エッジや組み込み用途でデータ同期を検討するチームには、長期運用の視点が参考になります。

### 4. Kimi K3.1 Pro と利用枠の実感 [V2EX]

[議論を読む](https://www.v2ex.com/t/1251425)

Kimi K3.1 Pro の性能と、短時間で消費される利用枠についての議論です。モデル評価では精度だけでなく、コンテキスト量、並列実行、リトライまで含めた一作業あたりのコストを確認する必要があります。社内導入では、速いエンドポイントが実際の待ち時間を減らすかを計測したいところです。

### 5. Personal Agent をどこまで任せるか [V2EX]

[議論を読む](https://www.v2ex.com/t/1251415)

個人用エージェントや定期実行の使い方を集めたスレッドです。最初は読み取り中心で、結果を人が検証でき、失敗しても元に戻せる仕事から始めるのが安全です。便利さを増やす前に権限と通知先を決めると、日常の自動化が壊れにくくなります。

### 6. Rust 向け parser generator、prpr [Zenn]

[記事を読む](https://zenn.dev/tanakh/articles/prpr-packrat-parser)

prpr は Rust 向けのシンプルで高速な parser generator として紹介されています。構文解析ツールは速度だけでなく、失敗時の診断が利用者に届くか、生成物を追えるかが採用の分かれ目です。DSL や設定ファイルを持つプロダクトでは、保守性の比較対象として面白い選択肢です。

### 7. 脆弱性管理を仕組みにする [Zenn]

[記事を読む](https://zenn.dev/dress_code/articles/be5550254695cd)

この実践記は、脆弱性対応を個人の頑張りではなく継続的な仕組みにする取り組みです。担当、期限、例外、受容したリスクを追跡できれば、アラートが増えても優先順位を説明しやすくなります。長期保守や複数ベンダーを抱える組織ほど、こうした台帳の効き目は大きいでしょう。

### 8. Agent Skills を財団へ寄贈 [Anthropic]

[発表を読む](https://www.anthropic.com/news/donating-agent-skills-to-the-agentic-ai-foundation)

Anthropic は、エージェント向けの専門知識と手順を表現する Agent Skills を Agentic AI Foundation へ寄贈すると発表しました。互換性だけでなく、Skill が要求する権限、配布元、更新履歴をツール間で追跡できるかが実務では重要です。社内 Skill を増やすなら、依存パッケージと同じように出所とレビューを管理したいものです。
